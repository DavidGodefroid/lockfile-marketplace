# Reviewing a plugin

A lockfile plugin answers one yes/no question about a file an AI agent must
never read. With one bit of output, the question itself, and what the code
really computes, are the only ways a plugin could leak what a file says. So
every plugin version is reviewed by a maintainer before it is released, and
CI alone is never enough.

CI already checks, on every pull request: the manifest against the
contract, the build (`CGO_ENABLED=0 -trimpath`), forbidden imports
(`scripts/importcheck`: no network, no `os/exec`, no `plugin`, no `unsafe`,
no raw system calls), pinned dependencies, and the conformance tests (every
fixture gives its expected answer in the lockfile sandbox, random and
truncated inputs give an answer or a clean failure, never a hang).

The reviewer checks what CI cannot:

- [ ] The question is about the format, structure, integrity or rendering
      of the file, never about what its content means or says.
- [ ] The code answers exactly the stated question, nothing more, nothing
      else.
- [ ] `one` and `zero` are unambiguous: a reader knows what each answer
      means without reading the code.
- [ ] Fixtures are synthetic, generated by the tests; no real document, no
      names, addresses or amounts.
- [ ] Dependencies are pinned and reviewed; a new dependency is justified.
- [ ] A changed `question`, `one` or `zero` is a new major version.

Examples of questions that are refused: "is the addressee a woman?", "is the
amount above 10 000?", "does page 2 contain the word X?". They are about
what the file says.
